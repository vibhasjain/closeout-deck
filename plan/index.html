The Framing: Automating the Middle & Back Office

Closeout Copilot unifies everything HyperTrack does: automating operations tasks in the middle and back office for staffing firms. The core value proposition — billing customers and paying workers faster and error-free.

Every session starts with:

"How can I help you bill your customers and pay your workers faster?"

Alternate framings the agent can use depending on context:

  • "How can I automate your operations tasks in the middle and back office?"
  • "How can I help you close out faster?" — once the customer is familiar with the closeout concept

The agent should discover additional natural openings through conversation — let the customer's own language guide the framing. Everything ladders up: scheduling, meal breaks, no-shows, time & attendance, reconciliation, payments.

● In Scope

  • Scheduling
  • Meal breaks / rest compliance
  • No-shows / attendance
  • Time & attendance tracking
  • Payments reconciliation
  • Worker communication
  • Facility verification

● Out of Scope (Agent Deflects)

  • Hiring workers
  • Winning contracts
  • ATS (applicant tracking)
  • Payroll systems (Gusto, ADP)
  • Non-staffing use cases

Baseline Requirements

The agent must confirm these three prerequisites before generating any blueprint:

1. Authority & ability to communicate with workers

Through an app, phone, email, or other channel. The staffing company must be able to reach their workers.

2. Authority & ability to talk to customers / facilities

The staffing company must have a relationship with the facilities where workers go.

3. Knowledge of shift intent

Who is supposed to visit which facility, when. Without this, there's nothing to close out against.

Synthesis

Three-Phase Solutioning Flow

The conversation progresses through three natural phases. The UX transforms as the customer moves deeper.

1

Qualification

Open-ended conversation. "Do you manage workers going to customer sites or facilities?" If no → deflect honestly ("Go to Gusto," or even "Delete your account — we have no joy in holding onto your email"). If yes → discover how they bill customers and pay workers today. Can also route to specific products: Closeout Copilot vs. location tracking.

UX: Full-screen chat. No diagram visible yet.

2

Situation Discovery

Targeted questions with quick-click multiple choice answers. "Is your worker app native or web?" "What's your system of record for timesheets?" Minimal cognitive load. One question at a time.

UX: Split screen emerges. Chat at bottom (25%), diagram at top (75%). Five empty boxes appear with pulsing outlines. Boxes fill in as questions are answered.

3

Blueprint Generation

Five boxes fully populated with customer-specific details. Arrows show integrations. Each component links to relevant SDK/API documentation. Internal Slack notification fires.

UX: Complete architecture diagram. Interactive — click nodes for docs, iterate via conversation. "What if we also wanted to track no-shows?"

"Anyone who starts using this has a phenomenal experience of, in a five-minute conversation, I got from my problem to my solution with a blueprint."

— Kashyap

Input Methods

Conversation

Primary method. Natural language dialogue. "Tell me what you want." The agent asks follow-up questions conversationally.

🌐

Website URL

📎

File Upload

Spreadsheets, presentations, PDFs. "I'm trying to get column D of this file done through a machine-assisted way." The agent extracts context and tailors questions.

Design Language

From Terminal Windows to Semantic Types

Currently every node looks the same — mac-style title bars in 4 colors. The new design language makes each element instantly recognizable by what it is, not just what color it's assigned.

Node Type System

Color is derived from semantic type. The LLM picks what something IS; the renderer knows how to draw it.

Type Represents Visual Treatment
Person Users & personas: Worker, Ops, Facility Manager Avatar circle, softer rounded shape, warm amber tones, no title bar chrome
App Mobile or web applications Device frame — phone outline for mobile, browser chrome for web, blue tint
Backend Server-side systems Hexagonal / server-rack aesthetic, solid borders, muted purple
SDK Code integration points Code bracket </> accent, monospace font, cyan tint, code-editor look
Cloud / SaaS Third-party services (Workday, ADP, etc.) Cloud shape outline, gray with service initial or logo
HyperTrack HyperTrack / HyperDrive components Distinctive green (#15803d), subtle glow effect, HT logo mark, gradient border
Closeout AI AI / Copilot intelligence layer Brain/sparkle icon, purple gradient border, subtle animation hint
Output Downstream: Payroll, HR, Accounting Arrow-out / export shape, warm muted tones

Edge (Connection) Types

API Call — solid line + method badge
SDK Embed — dashed with </>
Data Flow — animated flowing dots
User Action — dotted with person icon
Webhook — lightning marker

Architecture

Claude Agent SDK as the Thinking Engine

The current backend does single-shot OpenAI calls to generate diagram JSON. The solutioning agent needs multi-turn conversation, tool use, structured reasoning, and streaming. Claude Agent SDK provides all of this.

Why Agent SDK (Not Raw LLM Calls)

🔁

Multi-Turn Conversation

Session memory across the entire solutioning flow. The agent remembers what was asked and answered.

🔧

Tool Use

The agent calls tools: update_blueprint, show_quick_choices, qualify, search_docs, notify_team.

🧠

Structured Reasoning

Qualification logic, follow-up question selection, entity extraction, conflict resolution.

⚡

Streaming

Real-time conversation text + diagram updates via SSE to the frontend.

Agent Tools

update_blueprint

Modifies the architecture diagram — adds, updates, or removes nodes and connections. Returns updated diagram to frontend via SSE. The primary output mechanism.

show_quick_choices

Sends a multiple-choice question to the frontend. User clicks an option; response flows back as a user message. Keeps cognitive load low.

qualify

Internal tool. Marks the customer as qualified or not-qualified with a reason. If not qualified, triggers a deflection message with recommendations.

search_docs

Searches HyperDrive documentation to find relevant SDK/API docs. Links are embedded in blueprint nodes via docUrl.

notify_team

Sends a Slack notification when a blueprint completes. Customer name, conversation summary, blueprint link. "Boom, we're ready for a call."

Conversation Flow (Agent Perspective)

1
Customer opens solutioning page → agent introduces itself: "I'm your Closeout Copilot. How can I help you close out faster?"
2
Customer describes their problem in natural language
3
Agent uses qualify() internally. Not a fit? → deflect with recommendation. Qualified? → proceed.
4
Agent uses show_quick_choices() for targeted questions. Quick-click answers. Empty boxes appear in diagram.
5
After each answer, agent uses update_blueprint() to populate a box. Frontend animates the fill-in.
6
Complete blueprint generated. Agent uses notify_team() to alert internally via Slack.
7
Customer iterates: "What if we also wanted to track no-shows?" → blueprint updates in real-time.

Roadmap

Implementation Phases

Five phases, each independently shippable. Each builds on the previous.

Phase 1

Design Language Overhaul

Replace the 4-color terminal-window aesthetic with the semantic node type system. Same diagram editor UX, but nodes look visually distinct based on what they represent.

  • New type field replaces color on nodes
  • Distinct renderers per type (person, app, backend, SDK, cloud, HyperTrack, AI, output)
  • Edge types with visual differentiation (API, SDK, data flow, webhook)
  • Update LLM system prompt for new type vocabulary
Phase 2

Conversational Agent Backend

Replace the single-shot OpenAI call with a Claude Agent SDK-powered conversational agent. Multi-turn, tool-using, streaming.

  • Agent definition with system prompt (the "solutioning training")
  • Five tools: update_blueprint, show_quick_choices, qualify, search_docs, notify_team
  • SSE endpoint for streaming text + diagram updates
  • Session state management
Phase 3

Split-Screen Conversational UX

Transform the page from a prompt bar to a split-screen: chat at bottom, diagram progressively building at top.

  • Chat panel with message history, typing indicator, streaming
  • Quick-choice button component for multiple-choice questions
  • Phase transitions: full-screen chat → split screen → full diagram
  • Empty/placeholder boxes with pulsing outlines
Phase 4

Progressive Revelation & Polish

The wow factor: animations, doc links, internal notifications, session persistence.

  • Smooth fill-in animations when agent populates a box
  • Documentation URL links on nodes (click to open SDK/API docs)
  • Slack notification on blueprint completion
  • Website URL + file upload input methods in chat
  • Session persistence in PostgreSQL (replace localStorage)
Phase 5

Qualification Intelligence

Train the agent to actually qualify and route effectively. Honest deflection. Existing customer detection. Handles both new prospects and existing customers being onboarded onto Closeout Copilot.

  • Qualification criteria from HyperDrive's sales playbook
  • Deflection messages with alternative recommendations
  • Product routing: Closeout Copilot vs. location tracking vs. other
  • Pre-populate blueprints for existing production customers
  • Tailored onboarding paths for existing HyperTrack accounts vs. net-new prospects
  • Upsell identification ("these guys should totally be using on-shift also")
