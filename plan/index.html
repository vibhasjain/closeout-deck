Internal Game Plan

Solutioning Agent

Transform the solutioning page from a static diagram editor into an AI-powered conversational agent — the first interaction point for every Closeout Copilot customer. Five minutes from "hello" to a visual architecture blueprint.

Key Decisions Five-Box Model Design Language Architecture Phases
Synthesis

What Was Decided

The solutioning agent IS the Closeout Copilot

Not a separate tool. It's the first conversation a customer has with the product. Trust-building starts here. The agent is trained like a human solutioning hire — "Just the way I was training Ram to do solutioning... now we're just training an agent."

The Framing: Closeout

Opening question: "How can I help you close out faster?" — where "closeout" = getting paid by customers error-free + paying workers error-free. Everything ladders up to this: scheduling, meal breaks, no-shows, time & attendance, reconciliation, payments.

Out of scope (agent should deflect): hiring workers, winning contracts, ATS, payroll systems.

Three-Phase Solutioning Flow

1 Qualification
→
2 Situation Discovery
→
3 Blueprint Generation

Phase 1 — Qualification: Open-ended conversation. "Are you in the business of managing workers going to facilities?" If no → deflect ("go to Gusto", even "delete your account"). If yes → proceed.

Phase 2 — Situation Discovery: Targeted questions while diagram boxes appear empty. "Is it a native app? What framework? What's your system of record for timesheets?" Quick-click multiple choice, minimal cognitive load.

Phase 3 — Blueprint Generation: Five boxes populate with customer-specific details. Arrows between them show integrations. Each component links to docs.

Baseline Requirements the Agent Must Qualify

  • Authority and ability to communicate with workers (app, phone, etc.)
  • Authority and ability to talk to customers/facilities
  • Knowledge of who's supposed to visit which facility when (shift intent)

Input Methods

  • Conversation (primary)
  • Business website URL (scrape for context)
  • File upload (spreadsheets, presentations, PDFs)

Key UX Decisions

  • Conversation over wizards — "We need to get out of the wizard thinking mode."
  • Progressive disclosure — conversation → empty boxes appear → boxes fill in
  • Split screen — conversation at bottom (~25%), diagram at top (~75%)
  • One question at a time with quick-click answers
  • Slack notification when a blueprint completes
Canonical Architecture

The Five-Box Model

Every customer maps to the same 5 system components. Three user types: Worker, Customer/Facility, Ops. Two backends (theirs + ours). The language inside boxes is generative per customer; the structure is constant.

Visual System

Design Language

Replace the 4-color terminal-window aesthetic with a semantic node type system. The color field is replaced by type — color is derived from what something IS, not manually assigned. The LLM picks semantics, the renderer handles visuals.

Technical Design

Architecture

Claude Agent SDK as the Thinking Engine

Multi-turn conversation with memory, tool use (update_diagram, qualify_customer, search_docs, notify_slack), structured reasoning, and streaming — all out of the box.

Backend Structure

backend/
  app/api/solutioning.py       — SSE endpoint for agent conversation
  app/agents/
    solutioning_agent.py       — Claude Agent SDK agent definition
    tools/
      diagram.py               — update_blueprint, clear_diagram
      qualification.py         — qualify, route_product
      context.py               — scrape_website, parse_file
      notify.py                — slack_notification
    prompts/
      system.py                — Agent system prompt
      five_box.py              — Five-box architecture template

Agent Tools

  1. update_blueprint — Modifies the architecture diagram. Returns updated diagram via SSE.
  2. show_quick_choices — Sends a multiple-choice question to the frontend.
  3. qualify — Internal tool. Marks customer as qualified/not-qualified.
  4. search_docs — Searches HyperTrack docs to link in the blueprint.
  5. notify_team — Sends Slack notification when blueprint completes.

Session Persistence

  • Conversations stored in PostgreSQL (solutioning_sessions table)
  • Blueprint diagrams stored per session (not just localStorage)
  • Sessions linked to accounts — returning users see previous blueprints
  • "Erase all memory and start fresh" or "Start a new project"
Execution

Implementation Phases

Phase 1

Design Language Overhaul

Replace the 4-color terminal-window aesthetic with the semantic node type system. Same diagram editor UX, but nodes look visually distinct based on what they represent.

  • modify components/solutioning/types.ts New node/connection types
  • modify components/solutioning/DiagramRenderer.tsx Rewrite for semantic rendering
  • modify components/solutioning/DiagramRenderer.module.css Visual styles per type
  • modify components/solutioning/defaultDiagram.ts Update to new type system
  • modify backend/app/api/solutioning.py Update prompt for new types
Phase 2

Conversational Agent Backend

Replace the single-shot OpenAI call with a Claude Agent SDK-powered conversational agent. Multi-turn conversation, tools, and SSE streaming.

  • new app/agents/solutioning_agent.py Agent definition with tools
  • new app/agents/tools/*.py Agent tools (diagram, qualification, context, notify)
  • new app/agents/prompts/*.py System prompt and templates
  • modify app/api/solutioning.py New SSE endpoint for multi-turn
  • modify pyproject.toml Add anthropic + agent SDK
Phase 3

Split-Screen Conversational UX

Transform from prompt-bar to split-screen chat + diagram. Customer sees chat at bottom, diagram progressively building at top. Quick-click answers.

  • new components/solutioning/ChatPanel.tsx Chat interface
  • new components/solutioning/QuickChoiceInput.tsx Multiple choice UI
  • modify pages/SolutioningPage.tsx Split-screen layout
  • modify pages/SolutioningPage.module.css New layout styles
Phase 4

Progressive Revelation & Polish

The "wow factor" — empty boxes with pulsing outlines, smooth fill-in animations, doc links on nodes, Slack notifications, file upload, session persistence.

  • Empty/placeholder nodes with pulsing outline
  • Smooth fill-in animation when agent populates a box
  • Doc URL links on nodes (click to open SDK/API docs)
  • Slack notification on blueprint completion
  • Input methods: website URL field, file upload in chat
  • Session persistence (new DB table, replace localStorage)
Phase 5

Qualification Intelligence

Agent actually qualifies and routes effectively. Trained with HyperTrack's qualification criteria, deflection messages, product routing, and existing customer detection.

  • Train agent with HyperTrack's qualification criteria
  • Deflection messages with alternative recommendations
  • Product routing (Closeout Copilot vs. location tracking vs. other)
  • Existing customer detection (pre-populate from production data)
