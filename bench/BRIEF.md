# /bench build brief — Payroll Desk (Timesheets · Reconcile · Payroll · Rules)

Self-contained brief for the builder. Read fully before editing. The three files
you will touch: `bench/index.html` (CSS + DOM + UI script), `bench/engine.js`
(rules engine + synthetic data + node self-check), `bench/catalog.js` (36-pack
catalog, `window.CATALOG`). Nothing else in the repo changes. Logos live in
`/logos/` (some are being added in parallel — see "Logos").

## Context

Kashyap's direction from the 2026-09-08 call: work backwards from business value
(revenue protection / worker churn) into a product screen that looks like the
prospect's own world — "pick your UKG, Bullhorn, whatever… this screen is names of
workers and the pay, this is the pay cycle, these are the flags, this data is pulled
from UKG, this time data is from Bullhorn." The rulebook cannot be the first screen;
it sits *inside* that flow.

`/bench` (`bench/index.html`, Rulebook Workbench v2) already has the engine (25 live
rules + 36-pack catalog), one seeded pay week (Mon Aug 24 – Sun Aug 30 2026, 54
shifts, 14 workers, 6 facilities each on a different timekeeping system), the source
drawer, and the ShopStream design language. Its *sequence* and *density* are wrong
for the demo: it leads with rules/compile/vocabulary and exposes params, traces and
the feature vocabulary. Nothing underneath changes — we re-sequence and hide.

User spec (final, this session):
1. **Timesheets** — connect raw-data systems (UKG, ADP, Ubeya, Paylocity, 7shifts,
   TempWorks, Avionté, Deputy, Bullhorn…). Real logos. Click → mock connect flow
   (API key or browser sign-in). Doesn't have to really work.
2. **Reconcile** — the action. Left: pay cycles. Middle: all shifts in the cycle
   (workers and their pay, with which system each time source came from). Right:
   discrepancies spotted. Click a discrepancy → the rule we applied appears in the
   drawer, with a button to the source document. No params, no variables, no traces.
3. **Payroll** — connect the payroll / billing system (ADP, Gusto, Paychex,
   QuickBooks, Workday…) and see the pay run going out for the cycle.
4. **Rules** — kept, simplified (list → detail → source), plus "add a custom rule"
   (NL sentence → compiled draft, mocked).

Constraints: keep engine + data + drawer + design language; don't re-scrape rules;
ship on the site at the same URL; **commit + push when done** (user: "push it").
Light theme, ShopStream restraint rules in `tasks/lessons.md` (2026-08-31 entries).
Flag only: `payroll-src/PRODUCT.md:44` says not to claim integrations beyond the six
the site names — user has explicitly asked for UKG etc. on this internal, noindex
prototype, so we proceed.

## Decisions

- **Refactor `/bench` in place** (URL stays; memory + deck already point there).
- **Split into three files** so the node self-check can run: `bench/engine.js`
  (lines 309–1020 of today's file, incl. self-check), `bench/catalog.js` (1021–1490,
  `window.CATALOG`), `bench/index.html` (CSS + DOM + UI). `index.html` loads both via
  `<script src>`. No build step (bench isn't in the Netlify build command).
- **Four top tabs**: Timesheets · Reconcile · Payroll · Rules. Compile and Vocabulary
  tabs are deleted from the UI (their code + `COMPILES` data go; `FEATURES` stays —
  the engine needs it; the compile story lives on in `/decks/rule-compiler`).
- **Pay cycles = weekly**, 4 of them: current (open) + 3 prior (paid). Generated by
  parameterising `makeWeek()`; only the current week gets the 17 scripted `48xx`
  discrepancies.
- **Param steppers, traces, "Fires n/54" backtests, vocabulary values: not rendered.**
  Engine keeps `params`/`P()`/`overrides` untouched; UI just stops drawing them.
- **Connect flows are in-memory mocks** (status flips after a fake delay). No backend.
- **Custom rule compile is canned** (3 keyword templates + generic), no LLM call.
- Implementation is delegated to one builder subagent per the `fable-subagents`
  skill; Fable writes the brief (this file), reviews, runs the self-check, verifies
  headless with dev-browser, commits, pushes, checks the live URL.

## Engine edits (`bench/engine.js`)

1. `makeWeek(opts = {})` → `makeWeek({ seed = 20260824, scripted = true, start })`.
   Seed feeds the LCG (today hardcoded at lines 840/847); the scripted `48xx`
   override block (893–968) is wrapped in `if (scripted)`. Return value unchanged
   (array of shifts). Auto ids: prefix with the seed's week so ids don't collide
   across cycles (e.g. `5001` → `W17-5001` for prior weeks; current week keeps `5001`
   so existing asserts and deep links hold).
2. `DAYS` stays as the current-week labels; add `dayLabels(startISO)` → 7 labels
   like `'Mon 17'`; UI picks per cycle.
3. Replace the per-render `backtest()` loop (25 full engine runs per rules-queue
   paint) with `fireCount(run, ruleId)` computed from an existing run's rows (same
   predicate backtest uses). Keep `backtest()` exported — the self-check uses it.
4. Self-check additions: `makeWeek({seed:20260817, scripted:false})` has no `48xx`
   ids and > 45 shifts; `fireCount(run,'CA-MB-01') === backtest(week,'CA-MB-01').fires`.
   Run: `node bench/engine.js` (works once extracted — `module.exports` at 975
   already anticipates it).

## Tab specs (every tab = toolbar + queue | detail | aux, existing `.main` skeleton)

### 1 · Timesheets  (`#m-sources`)
- **Queue**: rows grouped by `.sect.lbl` headers (Time & attendance / Facility /
  Location / Manual). Row = 20px logo (grayscale, `filter:grayscale(1)`, full
  opacity when `.active`) or a 16px stroke icon for the non-brand sources · name ·
  status tag (`Connected` neutral · `Available` neutral · `Syncing` blue) · meta line
  `API · 1 site · synced 04:10` in `.count`. Toolbar: magnifier + chips
  `All · Connected · Available`.
- **Detail**: info-bar = logo + name left; right = `Connect` button (available) or
  `Sync now` (connected). Body: kv table *Method · Sites · Last sync · Records this
  cycle*; "What we pull" as neutral tags; "Field mapping" kv (their field → ours:
  `punch_in → clock in`, `punch_out → clock out`, `break_start/end → meal`,
  `schedule.start → scheduled`, `edit_log → edited after approval`). For `upload`: a
  dashed drop zone + `Choose file` button → fake parse → "Parsed 54 shifts · 6 sites
  · sent to Reconcile" and a `Open in Reconcile` button.
- **Aux** header `Feed`: the raw records that landed from this source this cycle —
  shifts at its sites, mono lines `Thu 27 · Maria R. · 08:58 → —` (raw punch, before
  the engine touches it; missing outs render as `—`). Empty state for available:
  "Nothing pulled yet."

### 2 · Reconcile  (`#m-reconcile`) — the demo screen
- **Queue** = pay cycles. Row: `Aug 24 – 30` + status tag (`Open` amber, `Paid`
  neutral); meta `54 shifts · 14 workers · $58,420`; row3 `17 flagged · 3 held ·
  cutoff Tue 18:00` or `paid Thu Aug 27`. Toolbar chips `All · Open · Paid`.
- **Detail**: info-bar left `Pay cycle Aug 24 – 30` + status tag; right = chips
  `All · Flagged · Held · Clean` (reuses `shiftFilter`) and, for open cycles, an
  `Approve cycle` button (mock: toast "41 workers approved · 3 held" — no state
  change needed beyond a tag). Body = one `table.sheet` **grouped by worker**:
  worker header row (name · role · `4 shifts · 31.5h · $771.75` mono), then shift
  rows: Day · Site · Sched · Punches (`08:58 → 17:01`, missing = `—`) · Source (tag
  with source name from `SOURCES`, plus a `GPS` / `Badge` tag when location evidence
  exists) · Hours · Pay · Δ vs sheet (mono `+$24.50` / `−$36.75` / `—`) · Status tag

- **Aux** header `Discrepancies` + `.count` (`17 · +$412 / −$1,207`): list of every

## Design language (must stay inside this set)
Inter for ALL UI text; mono only for data (ids, clock times, money, meta lines) plus
ONE label treatment (`.lbl`: mono 10.5 uppercase tracking-wide muted). Sizes in use:
10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 px — no others. Grayscale; color only as the
two tinted pills (`.tag.amber` = needs a human: Flagged/Open/Review; `.tag.blue` =
Held/Syncing). Every status is a `.tag` (Title Case), pass/neutral included — never
bare text, never a colored dot. Anything clickable that opens something is a `.btn`
outline button, never a floating link. Links (`.lnk`) are muted underlines. Queue
rows are `.case` with `border-l-2` selection. Toolbars are ONE row: magnifier that
swaps into a search input + filter chips (+ at most one outline button on the right).
Aux-pane headers are one quiet word (`Feed`, `Discrepancies`, `Batch`, `Source`).
Sentence case for all UI copy. No emoji, no gradients, no colored callout boxes.
Logos render grayscale (`filter:grayscale(1)`), muted opacity, full on selection.
